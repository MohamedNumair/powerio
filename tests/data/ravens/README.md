# MG-RAVENS fixtures

- `case3_balanced.json` is vendored byte exact from
  [lanl-ansi/MG-RAVENS](https://github.com/lanl-ansi/MG-RAVENS)
  (`examples/case3_balanced.json`, last touched upstream at commit
  `1ad686e236e7af72ed4fd7fb46f80ed66ae8e2ba`, `develop` branch checkout
  `094ad1163`). Apache-2.0 (Triad National Security, LLC / LANL, LA-UR-23-23229).
  It is PowerModelsDistribution's `case3_balanced` feeder expressed in the
  RAVENS `mgravens24v1` profile. Although electrically balanced, the document
  uses the **multiconductor** register (per-phase `EnergyConsumerPhase` /
  `ACLineSegmentPhase` records, `PerLengthPhaseImpedance` matrices), so the
  balanced transmission reader must refuse it with guidance rather than read
  it lossily — that refusal is what the tests pin.

Balanced-register documents for the reader/writer round-trip tests are
generated by `write_ravens_json` itself from the MATPOWER fixtures in the
parent directory (the format's balanced conventions come from upstream's
`ravens/parsers/mpc2ravens.py`, which needs a Python stack to run; the writer
tests assert those conventions value by value instead).
